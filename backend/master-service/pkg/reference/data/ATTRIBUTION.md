# Reference data attribution

The files in this directory are generated by
`backend/master-service/scripts/gen_reference_data` from the sources below and
embedded in the master-service binary. Each JSON file records the exact source
URLs, upstream commit/version and SHA-256 of every raw input in its header.

## regions.json — Indonesian provinces and kabupaten/kota

- Legal basis: Keputusan Menteri Dalam Negeri Nomor 300.2.2-2138 Tahun 2025
  tentang Pemberian dan Pemutakhiran Kode, Data Wilayah Administrasi
  Pemerintahan, dan Pulau, jo. Kepmendagri Nomor 300.2.2-2430 Tahun 2025.
  Codes are the Kemendagri codes (dotted, e.g. `32`, `32.73`).
- Machine-readable source: cahyadsn/wilayah, `db/wilayah.sql`,
  commit `d68e8d5516f969d1905d0b2940f20034becb0db7`
  (https://github.com/cahyadsn/wilayah). Only the province (1-segment) and
  kabupaten/kota (2-segment) rows are used; names are whitespace-trimmed and
  SQL-unescaped, otherwise kept as published.

## countries.json — ISO 3166-1 countries with English and Indonesian names

- Source: Unicode CLDR 49.0.0 (cldr-json tag `49.0.0`):
  `cldr-localenames-full/main/en/territories.json`,
  `cldr-localenames-full/main/id/territories.json`,
  `cldr-core/supplemental/codeMappings.json`
  (https://github.com/unicode-org/cldr-json).
- Selection: two-letter codes that have both an alpha-3 and a numeric code,
  excluding user-assigned codes (AA, QM-QZ, X*, ZZ), deprecated codes
  (AN, BU, CS, DD, FX, NT, SU, TP, YD, YU, ZR) and EU. Local change: the
  Indonesian name of PS is "Palestina".

## Regenerating

From `backend/master-service`, with the raw files downloaded into a fresh
directory (they are read as data only):

```
go run ./scripts/gen_reference_data \
  -wilayah <dir>/wilayah.sql -wilayah-commit <commit> \
  -cldr-en <dir>/en/territories.json -cldr-id <dir>/id/territories.json \
  -cldr-codemappings <dir>/codeMappings.json -cldr-version 49.0.0
```

The generator fails unless it finds exactly 38 provinces, 416 kabupaten,
98 kota and 249 countries, and re-validates its output before writing. Codes
are never removed in a later version: mark them `is_active: false` with
`replaced_by`, and append new codes to `../testdata/known_codes.txt`.
